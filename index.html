Instalar o Claude Code

A CLI oficial da Anthropic para programar com Claude diretamente no seu terminal. Este guia cobre instalação em macOS, Linux e Windows, primeiro login, e os arquivos de configuração que você vai mexer todo dia.

1. Quick start

Se você está com pressa, são cinco linhas. Cole no terminal:

# 1. Instalar (macOS / Linux)
curl -fsSL https://claude.ai/install.sh | bash

# 2. Verificar
claude --version

# 3. Entrar no diretório do seu projeto
cd ~/meu-projeto

# 4. Iniciar o Claude (REPL interativo)
claude

# 5. Já dentro do REPL, autenticar
/login
É só isso para começar. O resto do guia é para você entender o que aconteceu e como customizar.

2. Métodos de instalação

O Claude Code é distribuído como binário nativo. A instalação não exige Node.js. Escolha o método do seu sistema:

macOS / Linux

Instalador oficial via curl. Cai em ~/.local/bin:

curl -fsSL https://claude.ai/install.sh | bash

macOS (Homebrew)

Para quem prefere gerenciar via brew:

brew install --cask claude-code

Windows (PowerShell)

Instalador nativo:

irm https://claude.ai/install.ps1 | iex

Windows (winget)

Pelo gerenciador oficial da Microsoft:

winget install Anthropic.Claude

npm (legado)

Existia o pacote @anthropic-ai/claude-code no npm. Ainda funciona mas não é mais o caminho recomendado — o instalador nativo é mais rápido, não depende de Node, e atualiza sozinho.

# só se você realmente precisa do path antigo
npm install -g @anthropic-ai/claude-code

Verificar a instalação

claude --version
claude doctor   # checa permissões, path, login, autoupdate

3. Primeiro login

Na primeira vez que você roda claude dentro de uma pasta, ele abre o REPL e pede para autenticar. Você tem três caminhos:

  1. Claude Pro / Max (mais comum): dentro do REPL digite /login → o navegador abre, você autoriza, e pronto. Sem cartão de crédito separado, sem chave de API — usa a sua assinatura.
  2. Anthropic API key: defina ANTHROPIC_API_KEY no ambiente antes de subir o REPL. Útil para CI, servidores, e workflows automatizados.
  3. Amazon Bedrock / Google Vertex: empresas que já têm contrato com AWS ou GCP podem rotear o Claude pelo provedor de cloud — variáveis CLAUDE_CODE_USE_BEDROCK=1 ou CLAUDE_CODE_USE_VERTEX=1.
As credenciais ficam salvas em ~/.claude/.credentials.json (Linux/Windows) ou no Keychain do macOS (preferido, mais seguro). Você não precisa fazer login de novo a cada sessão.

4. Arquivos principais

O comportamento do Claude Code é controlado por arquivos espalhados em três escopos: usuário (vale para todos os seus projetos), projeto (vale só dentro daquele repo) e local (não vai para o git). Memorize esta tabela — é o mapa mental que faz a diferença entre usar o Claude como brinquedo ou como ferramenta de produção:

ArquivoLocalPara quê serve
CLAUDE.md essencial ~/.claude/CLAUDE.md (global)
./CLAUDE.md (projeto)		 Instruções permanentes que entram em todo prompt. Convenções de código, comandos de build/teste, regras de estilo, contexto do produto. Carregado automaticamente ao iniciar o REPL na pasta.
settings.json ~/.claude/settings.json (usuário)
.claude/settings.json (projeto)
.claude/settings.local.json (local, gitignored)		 Configuração estruturada: modelo padrão, hooks, ferramentas permitidas/negadas, MCP servers, perfil de permissões. O settings.local.json é onde vai o que não pode entrar no git (tokens, paths absolutos).
.claude/skills/ ~/.claude/skills/<skill>/SKILL.md
.claude/skills/<skill>/SKILL.md		 Procedimentos repetíveis (recipes) que o Claude carrega sob demanda. Cada skill é uma pasta com um SKILL.md que tem frontmatter name + description. Use para regras de negócio, deploy steps, padrões de PR, etc.
.claude/agents/ ~/.claude/agents/<agent>.md
.claude/agents/<agent>.md		 Subagentes especializados que rodam em contexto isolado. Use para code review, exploração de codebase, pesquisa, ou qualquer tarefa que você queira delegar sem poluir o contexto principal.
.mcp.json ./.mcp.json (projeto) Servidores MCP (Model Context Protocol) que dão ao Claude acesso a ferramentas externas: Playwright, Supabase, GitHub, sistemas internos. Compartilhado com o time via git.
Slash commands customizados ~/.claude/commands/<cmd>.md
.claude/commands/<cmd>.md		 Atalhos do tipo /deploy, /test, /review. Cada comando é um .md com o prompt — Claude executa quando você digita o slash no REPL.
Auto-memória ~/.claude/projects/<slug>/memory/ Sistema persistente que o Claude usa para lembrar fatos sobre você, feedback recebido e contexto do projeto entre sessões. Atualizado automaticamente — você não precisa editar.
Histórico de sessões ~/.claude/projects/<slug>/*.jsonl Transcrição completa de cada conversa. Útil para auditoria, debug, ou para reprocessar uma sessão antiga.
Regra de ouro: escreva um CLAUDE.md no seu projeto antes de qualquer outra coisa. Liste comandos de build, padrões de commit, convenções do código e o que está fora do escopo. É o investimento de 10 minutos que mais paga ao longo do tempo.

5. Comandos essenciais dentro do REPL

ComandoO que faz
/helpLista todos os comandos disponíveis
/login / /logoutAutentica ou desconecta a conta
/initCria um CLAUDE.md inicial baseado no seu projeto
/clearLimpa o contexto da conversa atual
/compactCompacta o histórico para liberar contexto sem perder o fio
/modelTroca o modelo (Opus, Sonnet, Haiku)
/agentsLista subagentes disponíveis
/mcpMostra status dos servidores MCP conectados
/costMostra consumo de tokens da sessão
!<cmd>Executa um comando shell e injeta a saída no contexto
Esc EscEdita a última mensagem que você enviou

6. Próximos passos

  • Rode /init num projeto seu — o Claude vai gerar um CLAUDE.md inicial baseado no que ele lê do código.
  • Adicione o primeiro skill: crie .claude/skills/meu-deploy/SKILL.md com o frontmatter name + description e um passo-a-passo do seu processo de deploy. Da próxima vez que você pedir para fazer deploy, Claude carrega o skill e segue.
  • Configure um servidor MCP: o .mcp.json pode ligar Claude ao Playwright (testes de browser), Supabase (queries diretas), ou ao GitHub (PRs e issues sem sair do REPL).
  • Compartilhe o .claude/ do projeto com o time via git. settings.local.json fica gitignored — o resto vira convenção do time.
